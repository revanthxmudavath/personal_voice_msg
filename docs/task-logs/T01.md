# T01 — Repository and no-mock test foundation

## Scope

- Minimal Python 3.12 package managed by `uv` in a project-local `.venv`.
- Fast repository-policy tests for mocks, lockfile freshness, planted credentials,
  and GitHub workflow YAML.
- Ruff, mypy, pytest markers, concise development documentation, and CI.
- No production application behavior.

## Audit hardening on 2026-07-21

An independent T01-T05 audit reproduced policy bypasses that the earlier scan
did not cover. Ten new red cases proved that syntax-invalid or non-UTF-8 Python
was silently skipped, dynamic `pytest.MonkeyPatch`/`unittest.mock` imports were
not detected, and sensitive voice, session, recipient, token, and private-key
artifacts could pass the secret scan.

The policy now:

- fails closed when a Python file cannot be parsed or decoded;
- detects the bounded dynamic mock-access forms demonstrated by the audit;
- rejects known recipient, WAHA token/session, voice-embedding, and private-key
  artifact names before attempting text decoding;
- rejects private-key markers in otherwise ordinary text files; and
- permits explicitly named `.example` documentation fixtures.

Focused T01/T02 verification after the fixes: `60 passed`. Ruff, strict mypy,
the lockfile check, and the full repository-policy command were clean.

Static policy cannot prove the absence of every runtime-generated import or an
unknown provider-token format. New integration code remains subject to review,
and provider-specific token patterns must be added when T15 selects the final
WAHA credential format. Git-history and image/artifact scanning remain part of
the T18 hardening gate.

## Second audit hardening on 2026-07-21

A second independent review added red coverage for three indirect no-mock
forms: `pytest.mark.usefixtures("monkeypatch")`,
`request.getfixturevalue("monkeypatch")`, and
`__import__("unittest.mock")`. The AST policy now rejects those bounded forms.

Secret scanning no longer skips files over one megabyte or undecodable files.
It reads complete bytes, checks UTF-8 and UTF-16 representations, and fails
closed when content cannot be inspected. The `.example` exemption is now
limited to a final `.example` suffix or `.example` before a documentation
suffix, so `owner.example.embedding` is rejected. Public certificate PEM files
are allowed while private-key markers remain prohibited.

The focused T01/T02 suite passed `71` tests and the complete fast suite passed
`209`. Repository-history and container image scanning remain T18 work and are
now explicit in the implementation plan.

## CI and workflow-policy remediation on 2026-08-01

The cumulative T01-T09 audit found that the workflow checker accepted any
nonempty `jobs` mapping and did not require immutable third-party action
references. New red tests exercised a non-mapping job, the specific nonempty
`nonsense: true` job, missing `runs-on` or `steps`, non-mapping and
non-executable steps, and moving `@v7` and `@main` action references. Before
implementation, the workflow subset reported `7 failed, 8 passed` because all
seven invalid fixtures were accepted.

The checker now requires every job to be a mapping. A normal job must contain
`runs-on` and a nonempty list of mapping steps, with each step providing a
nonempty `run` or `uses` value. Job-level reusable workflows remain valid.
Local `./` references are allowed; every non-local job-level or step-level
`uses` reference must end in a full 40-hex commit SHA.

The official GitHub repository refs were independently queried with:

```powershell
gh api repos/actions/checkout/git/ref/tags/v7
gh api repos/astral-sh/setup-uv/git/ref/tags/v9.0.0
```

Both refs were lightweight tags pointing directly to these reviewed commits:

- `actions/checkout` tag `v7`:
  `3d3c42e5aac5ba805825da76410c181273ba90b1`
- `astral-sh/setup-uv` tag `v9.0.0`:
  `c771a70e6277c0a99b617c7a806ffedaca235ff9`
