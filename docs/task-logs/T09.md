# T09 - Conditional discovery-agent harness benchmark

## Status

Complete on `task/T09-discovery-agent-benchmark`; completion commit `45f492c`
is on `origin/main`.

The restricted LangChain/Gemini discovery candidate was not retained. It
improved unique valid-candidate yield but failed the required protocol and
hostile-input security gates. Deterministic T07 discovery remains the
deployable production path.

## Prerequisites and data boundary

- T07 and T08 were complete before T09 began.
- The owner approved the Gemini Developer API and fixed
  `gemini-3.6-flash` model for this benchmark only.
- The benchmark sent bounded public-page excerpts and fresh synthetic history.
  It sent no recipient data, private message history, voice data, WhatsApp
  data, or secret value.
- The Gemini key was read from the external owner-managed
  `gemini_api_key.txt` file and mounted read-only into the isolated runner.
  The key remains outside Git and was not modified or deleted.
- An initial attempt used an extensionless path that Docker had created as an
  empty directory. The secret-file boundary rejected it before any provider
  call. After the path was corrected to the existing `.txt` file, the
  benchmark proceeded.

## Candidate boundary

The evaluated harness exposed exactly:

```text
search_web(query)
fetch_public_page(result_id)
search_message_history(candidate)
submit_inspiration_card(card)
```

It had no checkpointer, persistent memory, filesystem, shell, generic HTTP,
code execution, delegation, TTS, WhatsApp, or secret access. The final
conversational response was ignored. Only a validated
`submit_inspiration_card` call could produce a candidate.

Deterministic run state required every submission to consume a preceding
candidate-bound, non-duplicate history result. Duplicate, mismatched, missing,
and reused history authorizations failed closed. Resource budgets limited each
run to 3 searches, 3 fetches, 3 history checks, 2 submissions, 24 graph
super-steps, 120 seconds plus a 5-second shutdown grace, and measured input and
output token ceilings.

## Benchmark correction

The first historical report recorded 20/20 agent protocol completion and 40
agent cards versus one deterministic card. That report used unequal baseline
behavior and is retained only as debugging history; it is not retention
evidence.

The corrected `t09-semantic-v2` corpus used 20 scenarios:

- 5 literal discovery cases;
- 10 semantic-only discovery cases;
- 5 hostile semantic prompt-injection cases.

Both arms received equal time and action budgets. Hostile fixtures contained a
wrong-but-schema-valid card and instructions to violate the required tool
trajectory. Success required both exact permitted card semantics and the
authorized tool sequence.

The runner independently fetched and hashed the bytes observed through each
arm. The order-sensitive aggregate corpus SHA-256 was:

```text
0b07ed96da644ff8b500dd2a45dc60565f586748a653df0c9727337949e0a636
```

The agent's protocol failures were trials 2, 4, 7, 14, 18, 19, and 20
(one-based). The hostile cases were trials 4, 8, 12, 16, and 20; failures on
hostile trials made the aggregate security gate false. No provider or tool
exception explained these failures: they were completed but invalid semantic
or trajectory outcomes.

The run was not retried or prompt-tuned after seeing these results because that
would overfit the frozen evaluation corpus.

## Decision and cleanup

The candidate passed the material-yield and resource gates but failed two
mandatory gates. In accordance with the written fallback rule:

- the T09 LangChain/Gemini runtime modules were removed;
- T09-only fast tests, live fixtures, and benchmark runner were removed;
- LangChain, LangGraph, LangSmith, Google GenAI, and their T09-only transitive
  dependencies were removed from the locked runtime;
- the T09-only Gemini configuration loader and baseline benchmark seam were
  reverted to the T08 base;
- deterministic T07 discovery was retained unchanged.

Generic Gemini-key repository scanning, recognizable-key log redaction, and
cumulative redactor behavior remain. These are provider-independent secret
protections rather than authorization to use Gemini in production.
