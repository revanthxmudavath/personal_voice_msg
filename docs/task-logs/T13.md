## Two design decisions made explicit before coding (Karpathy guideline 1)

- **Input format scope**: `validate_sample` accepts only formats
  `soundfile`/libsndfile read natively (WAV/FLAC/OGG) and rejects anything
  else (e.g. `.m4a`/`.mp3`) as `"unsupported or unreadable audio format"`.
  FFmpeg-based transcoding of arbitrary upload formats is explicitly **not**
  added to T13 — `AGENTS.md`'s "Confirmed state" note ties FFmpeg's
  introduction to T14 ("FFmpeg and ffprobe are not installed; they are
  required before T14"), and adding it early for input normalization would
  be exactly the speculative-dependency pattern Karpathy guideline 2 warns
  against. In production this means: upload a WAV.
- **VPN sequencing gap**: the plan's "Upload only through the administrative
  VPN" describes T18 infrastructure that does not exist yet. T13 exposes a
  plain local file-path entry point (`enroll_voice(sample_path,
  destination)`) with no VPN-checking logic — there is no real VPN to check
  against yet, and stubbing one would be speculative. VPN-only transport
  enforcement is deferred to T18, which owns the actual network boundary.

## Implementation

New module `src/personal_voice_msg/voice_enrollment.py`:

- `EnrollmentError(ValueError)`.
- `validate_sample(path)`: reads via `soundfile`; rejects unsupported
  format, `< MIN_ENROLLMENT_SECONDS = 3.0s` duration, silence
  (`RMS < SILENCE_RMS_FLOOR = 0.001`), and clipping (`>1%` of samples at
  `|amplitude| >= 0.999`).
- `enroll_voice(sample_path, destination, *, model=None)`: validates, loads
  (or reuses an injected) `pocket_tts.TTSModel`, extracts the voice state
  via `get_state_for_audio_prompt`, exports it with `export_model_state`,
  **reads the exported file back** via `safetensors.torch.load_file` to
  verify it is non-empty before deleting the raw sample, then deletes
  `sample_path`. Deletion only happens after verified export, satisfying
  "delete the raw enrollment recording after the embedding is verified"
  literally, not just approximately.

"Discovery and sender identities cannot read the embedding" — enforced via
this codebase's existing pattern (narrow per-subsystem typed config, e.g.
`generation`'s `GeminiSettings` already has no `voice_embedding` field, and
`discovery` takes no settings object at all). Rather than asserting that by
inspection once, `tests/security/test_voice_enrollment_boundaries.py` makes
it a standing, automated guarantee: real AST parsing of every `.py` file
under `discovery/`, `generation/`, and `judging/`, asserting none of them
import `pocket_tts`, import `personal_voice_msg.voice_enrollment`, import
`Settings`/`load_settings` from `personal_voice_msg.config`, or reference an
attribute/name called `voice_embedding`. The detector was verified against
a real violation before trusting it (running it against
`voice_enrollment.py` itself correctly flagged its `pocket_tts` import) —
not written blind. **Scope note**: "sender" doesn't exist as code yet
(T15/T16); this test can only bind the subsystems that currently exist. It
must be extended to whatever module becomes the sender when T15/T16 build
it — noted here so it isn't rediscovered from scratch, same pattern as
T11b's `EXPECTED_SCHEMA_V1_OBJECTS` note.
