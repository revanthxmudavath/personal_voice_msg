## Design summary

Full design: `docs/superpowers/specs/2026-08-20-t17b-daily-send-entrypoint-design.md`.
Full plan: `docs/superpowers/plans/2026-08-20-t17b-daily-send-entrypoint.md`.

`poll_inbound_stop` (`consent.py`, T17) and `run_daily_send` (`delivery.py`, T16b)
had no caller anywhere in the codebase — this task gives them their first real
caller, narrowly, without changing either function or any of `sender.py`/
`database.py`.

- **`src/personal_voice_msg/daily_send_entrypoint.py`** (new): `run_daily_entrypoint`
  — checks whether the `DAILY_SEND` trigger is currently due (pure no-op, no DB/
  network touched, otherwise), polls once for STOP (`except TelegramPollError: pass`
  — poll fragility must never block a legitimate send), then delegates to
  `run_daily_send`. Short-lived by design: no internal sleep loop, no daemon, no
  process supervision — matches every idempotency mechanism already in this
  codebase being built around "safe to call repeatedly, cheaply."
- **`scripts/run_daily_entrypoint.py`** (new): the runnable CLI an external timer
  (cron/systemd — T18's concern) invokes every 1-2 minutes. `--config`/`--database`,
  both required. Loads real settings/secrets, constructs a real `Database`, calls
  the entrypoint once, prints the resulting state, and exits — non-zero on
  `FAILED`/`DELIVERY_UNKNOWN` (so cron's own job-failure signal actually fires on
  the states `delivery.py` says must be "surfaced for the owner to check") or an
  unhandled exception (redacted via `Settings.redactor()` before printing, so no
  secret reaches stderr/a log file — see Independent review finding 1).
- **Accepted, documented risk** (not fixed, human-adjudicated): `poll_inbound_stop`
  only runs inside the 5-minute `DAILY_SEND` window, not on every cron tick all day,
  matching the approved design spec's explicit no-op boundary. A STOP sent shortly
  after the window closes waits up to ~24h for the next poll — Telegram drops
  unfetched updates after 24h — and on the Pacific DST fallback day the gap between
  windows is 25h, so a STOP sent in roughly a one-hour band that one day per year
  could be dropped before ever being polled. Independent backstops (blocked-by-user
  403, admin kill switch) do not depend on this poll. Flagged for a T19 follow-up
  (poll-failure/missed-STOP alerting), not addressed here.

## Independent review

Dispatched on the most capable available model per this project's Model Selection
guidance for security-sensitive final review. Verdict: **"Ready to merge? With
fixes."**

**Important (4, all fixed):**
1. `scripts/run_daily_entrypoint.py` let an unhandled exception propagate raw to
   stderr; a real `AudioPipelineError` from a synthesis failure embeds the raw
   voice-embedding path (a value `Settings.redactor()` itself classifies as
   secret), which under cron reaches a log file. Fixed: the top-level exception
   (after `settings` loads) is caught, redacted via `settings.redactor()`, printed,
   and re-raised as `SystemExit(1)`. The one exception that can occur *before*
   `load_settings` succeeds (nothing secret loaded yet) still propagates raw.
2. The script exited 0 for every `MessageState`, including `FAILED`/
   `DELIVERY_UNKNOWN` — states `delivery.py`'s own docstring says must be "surfaced
   for the owner to check," with no alerting built yet (T19). Fixed: a new
   `_exit_code_for` returns 1 for those two states, 0 otherwise (including `None`/
   "not due, skipped").
3. **Human-adjudicated, plan-text conflict — kept as designed, not fixed**: the
   entrypoint only polls inside the 5-minute window per the approved design spec's
   explicit text. See "Accepted, documented risk" above.
4. `tests/security/test_daily_send_entrypoint_fault_injection.py` gated its entire
   module on `T13_VOICE_SAMPLE`, even though the STOP-ordering test never reaches
   real TTS synthesis (sending is disabled before `produce_voice_note` is ever
   called). Fixed: only the two TTS-dependent tests skip without a real voice
   sample; the STOP-ordering test — this branch's core security property — now
   runs in any environment, no real voice sample required.

**Minor (3 fixed, 2 no action needed):** `_RoutingServer.stop()` no longer raises an
uncaught `OSError` from its accept-loop thread on shutdown; `_RoutingServer`'s
recorded `paths_seen` no longer contains the bot token (relevant since Task 5 runs
this exact file against a real token); the design spec's `TELEGRAM_API_BASE`
description corrected to match the actual (better) implementation, which imports
it from `sender.py` rather than defining a third duplicate copy. Two findings
(duplicated trigger-lookup expression at 2 call sites; a Windows-specific
backslash-doubling redaction edge case that does not reproduce on the real Linux
production target) were judged not to need action — recorded, not silently
dropped.

Fix-wave commit: `85b9ac7..4c99816`. Scoped re-review: all 6 findings ADDRESSED, no
new Critical/Important breakage in the fix diff. One residual Minor (an
undocumented POSIX-path-assumption comment near the `redact(str(exc))` call) was
parked rather than triggering a third review round — real but cosmetic, and the
redaction behavior was independently verified correct on the real Linux production
